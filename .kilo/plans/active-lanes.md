## Per-lane rules

### Test agent

- Owns the test surface.
- **EXCEPTION:** the test agent MAY edit `utils-server/rentalDispatchChain.ts` for race-condition guards (the F1-F4 + Item 2 #1 work). This exception exists because the race-condition guards in the implementation file are test-defining invariants. **No other implementation file is in scope.** If the test agent finds an implementation bug while writing tests, it files a finding and stops, instead of fixing.
- The test agent's prior commit `9b3d393` introduced forward references in `rentalDispatchChain.ts:129` and `:461`. **The test agent fixes its own bug as the first action on resume.** See `.kilo/plans/test-agent-resume.md`.
- Before each commit, the test agent appends the file scope to "Recent commits" below.

### Implementation agent

- Owns the marketplace implementation surface.
- The implementation agent does NOT edit `utils-server/rentalDispatchChain.ts` — the test agent owns the next commit on that file (the forward-reference fix). If the implementation agent needs a sweep emit in that file, it coordinates with the test agent first. Default: don't edit.
- Before each commit, the implementation agent appends the file scope to "Recent commits" below.

### Orchestrator

- Reads all commits, verifies against specs and prior commitments, files findings.
- May write small race-condition guards (e.g., adding `isNull(assigned_driver_user_id)` to a WHERE clause) when explicitly coordinated with the implementing lane. The orchestrator does NOT compete with the implementation agent for surface ownership.
- Files findings at `.kilo/plans/findings/<date>-<topic>.md` or in the round's close-out reply.
