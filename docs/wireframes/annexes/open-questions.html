Role-gated Admin dashboard, driver queue, config, packages, incentives, promos, preferences, referral campaigns, point offers, vehicle models, sample media, platform config, monitoring Requires verified admin/driver role and RLS policies that could not be granted during documentation. High Assign admin role in staging; run API route smoke tests with requireRole to verify each gated screen.
Permissions Location picker, map search, notification opt-in, camera/document upload OS-level permission dialogs are outside app control; static wireframes cannot trigger grant/deny flows. Medium Capture iOS and Android permission states manually; add to test matrix (see TD-01).
Device-specific Tablet layouts, iOS notch/safe-area, Android navigation bar, foldable split-screen Documentation run on desktop; no physical tablets or emulators with varying DPI/aspect ratios. Medium Test on iPhone SE, iPhone 15 Pro Max, Pixel 7, and a 10\" tablet; verify no overflow.
Edge states Empty rides list, empty wallet, zero calls remaining, no nearby drivers, no vehicles available Cannot seed negative or boundary data in production-like environments without fixtures. Medium Add seeded fixtures for each empty state; document fallback UI and retry affordance.
Dynamic params Ride detail [rideId], payment receipt [id], date-filtered screens Dynamic segments depend on live DB records; no UUIDs available during static documentation. High Create staging rides/payments; exercise every [id] route with real IDs.
Payment WebView PortPos success, failure, pending, and callback verification flows WebView requires live PortPos invoice; sandbox credentials unavailable for documentation. High Use PortPos sandbox; assert callback signature, invoice matching, and wallet credit. See lib/portpos.ts.
WebSocket ride:offer, fetch:confirm, ride:expired, ride:cancelled, location:update WebSocket events require active dispatch chain and real-time socket connection not available in static docs. High Run utils-server locally; simulate each event via test harness or Postman WebSocket client.
Deep links /track, ride share links, driver invite links Deep links require app registration and OS intent handling; cannot be opened from browser docs. Medium Register schemes in app.json; test via adb shell am start and XCUITest.
Offline Network-loss banner, offline ride request queue, sync-on-reconnect Cannot simulate sustained offline or flaky network from static documentation environment. Medium Use airplane mode and Charles Proxy throttling; verify queue persistence and retry logic.
Permission denied Location off fallback, notifications blocked, camera denied, storage denied Denied states require pre-configuration of OS permissions; not reproducible in fresh emulator. Medium Pre-configure denied permissions in test profiles; verify graceful degradation and re-prompt flow.
